# 渠道接入模块 UX 审查优化设计

## 背景

渠道接入中心已经支持组织级与工作区级渠道配置，但当前 UI 将登录、组织、作用域、配额、模型渠道和媒体服务堆叠在同一弹窗中。用户需要审查整个模块，并优化用户使用体验、视觉效果、UI/UX 与业务逻辑。

## 问题

- 工作区作用域在未选择工作区时仍可被选中，保存逻辑会静默落到组织级路径，容易造成配置范围误判。
- “测试”按钮实际只执行格式和已保存密钥复用校验，不会真实请求上游模型，文案存在误导。
- 工作区模式下用户看不出当前配置来自组织继承还是工作区覆写。
- OpenAI 兼容渠道的 protocol、path、payload 差异缺少解释，用户容易把 Chat Completions 和 Responses 混用。
- 渠道行视觉层级偏弱，状态、字段和操作按钮缺少分组。

## 目标

- 无 workspace 时明确阻止工作区级保存或校验，不发生静默降级。
- 将“测试”改为“校验配置”，并保留当前仅做格式校验的真实语义。
- 在面板顶部提供当前作用域摘要，说明组织级/工作区级的生效范围。
- 在渠道行展示配置来源和密钥状态，让用户区分组织继承与工作区覆写。
- 为 OpenAI 兼容渠道增加协议说明，降低错误配置概率。
- 优化面板视觉层级和表单布局，不改变核心接口契约。

## 非目标

- 不在本轮接入真实上游 live probe。
- 不改动渠道数据库 schema。
- 不重构整个 Comparison Lab。

## 验收

- DOM 测试覆盖工作区未选择时的阻断提示、按钮文案、OpenAI 协议提示和配置来源展示。
- Hook 逻辑测试覆盖无 workspace 时工作区保存被阻止，且不会调用组织级保存接口。
- 相关渠道测试、DOM 测试、lint/build 和 `git diff --check` 通过。
