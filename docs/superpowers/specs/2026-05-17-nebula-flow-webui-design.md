# Nebula Flow WebUI 设计规格

## 背景

当前 WebUI 已具备完整编辑器壳层，但首屏仍偏传统深色工具面板：顶栏、左栏、中央预览、右侧属性与时间轴视觉权重接近，AI 导演入口没有形成旗舰能力记忆点。2026-05-17 的运行态截图来自 Docker 网关 `http://127.0.0.1:18081`，页面健康检查返回 `{"status":"ok"}`。

## 目标

- 将首屏空态从“等待导入”改为“AI 导演工作台已就绪”。
- 以 Nebula Flow 视觉语言建立深渊底色、极光高光和 AI 算力在场感。
- 第一轮只做可落地的 UI 壳层改造，不重写业务流程，不改后端契约。
- 左侧导航从宽标签组降噪为命令轨道，并突出 AI 导演为核心入口。

## 范围

- `AppCenterPanel` 的剪辑空态结构和文案。
- `AppTimeline` 的空态行动区视觉语义。
- `App` 左侧入口的标识与可测试结构。
- 主题 token 与最后覆盖层 CSS。
- 相关 DOM 契约测试。

## 非目标

- 不实现真实 AI 对话面板。
- 不引入 Lottie、Canvas 或 WebGL 动画。
- 不变更素材导入、导演生成、导出 API。
- 不重写整体布局状态管理。

## 验收标准

- 中央空态包含 `Director's Canvas` 语义、Nebula Flow 标识、导入素材卡片与唤醒 AI 导演卡片。
- AI 导演入口在左侧命令轨道中具备独立可测试标识。
- 时间轴空态保留独立 CTA rail，且 AI 编排按钮具备 AI 强调语义。
- 相关 DOM 测试先失败后通过。
- 浏览器运行态可打开，控制台无新增 error。

## 第二轮补充

浏览器复核发现第一轮 `55-app.css` 已被打包，但中央 launchpad 和时间轴 AI CTA 的部分视觉属性被 `54-app.css` 中更高特异性的运行态修正规则覆盖，表现为 deployed computed style 中 `background-image: none`。第二轮补充要求：

- Nebula Flow 关键覆盖必须使用 `html[data-theme] body .monitor-stage-shell.is-idle ...` 级别的主题作用域特异性。
- 中央 launchpad 的渐变背景、28px 圆角、外发光和 520px 画布宽度必须在 Docker 页面真实 computed style 中生效。
- 中央 AI 卡片与时间轴 AI CTA 的 AI-first 渐变和阴影必须在部署态生效。
- CSS 守卫测试必须覆盖这些高特异性选择器，避免后续新增修正层再次压掉视觉方向。

## 第三轮补充

第二轮后视觉样式已在部署态生效，但左侧 AI 入口、中心 launchpad、底部时间轴 CTA 仍偏“各自发光”，缺少明确的工作流叙事。第三轮补充要求：

- 左侧 `AI 导演` 入口应暴露 `Core` 徽标，强调它不是普通工具页签。
- 中央 launchpad 应显示 `Prompt / Shots / Timeline` 三段式创作链路，表达从提示词到镜头再到时间轴的生产路径。
- 时间轴 AI CTA 应显示轻量 `Queue` 队列标记，承接中心创作链路的落轨语义。
- 第三轮视觉桥接样式独立放入最终 CSS layer，避免污染前两轮特异性修正。

## 第四轮补充

第三轮后左侧、中心和时间轴已形成 `Prompt / Shots / Timeline` 主链路，但右侧属性面板空态仍停留在传统“未选中片段”提示，导致首屏右侧与 AI 工作流割裂。第四轮补充要求：

- 右侧壳层应暴露 `inspector-console` 语义，表明它是镜头落轨后的检查控制台。
- 右侧空态应保留“未选中轨道片段”的可理解文案，同时补充 `Inspector Console` 记忆点。
- 右侧空态应显示 `Inspect / Tune / Render` 三段式检查链路，承接时间轴队列后的调参与交付语义。
- 第四轮样式独立放入新的最终 CSS layer，避免改写 `PropertyInspector.css` 的业务表单样式。
- 由于 `PropertyInspector.css` 是懒加载 CSS chunk，右侧空态关键背景/边框必须在组件 CSS 中也具备高特异性兜底，防止部署态 CSS 顺序覆盖。

## 第五轮补充

第四轮后左侧、中心、时间轴和右侧检查台已经连成主链路，但顶栏仍像传统工具栏，只显示品牌、模式、主题、画幅和导出，缺少全局创作流总控记忆点。第五轮补充要求：

- 顶栏应暴露 `Director Flow` 总线语义，表达当前页面由 AI 导演流统一调度。
- `Director Flow` 应显示 `Prompt / Shots / Timeline / Inspect / Render` 五段式链路，串起前四轮已落地的创作、落轨、检查和交付语义。
- 该结构必须是只读状态胶囊，不改变模式切换、主题、画幅和导出交互。
- 第五轮样式独立放入新的最终 CSS layer，避免回改早期顶栏密度和响应式修正规则。

## 第六轮补充

第五轮后顶栏已经具备全局流总线，但中央预览底部仍是传统播放器工具条，只显示运输控制、片段数、画幅和实验室入口，缺少从预览到实验室再到交付的输出语义。第六轮补充要求：

- 中央 `monitor-bottom-bar` 应暴露 `output-dock` 语义，表达它是预览与交付前的输出停靠区。
- 输出停靠区应显示 `Preview / Lab / Render` 三段式链路，承接右侧 `Inspect / Tune / Render` 后的交付路径。
- 该结构必须是只读状态，不改变播放、跳转、画幅展示和“视频实验室”按钮行为。
- 第六轮样式独立放入新的最终 CSS layer，避免污染播放器控制按钮与前五轮样式。

## 第七轮补充

第六轮后中央预览底部已有输出停靠区，但底部时间轴顶端状态条仍停留在 `待命 / GPU / MEM` 的传统监控信息，缺少轨道装配、同步检查和交付准备的队列语义。第七轮补充要求：

- 时间轴状态条应暴露 `timeline-bus` 语义，表达它是镜头从落轨到检查再到交付的装配总线。
- `Timeline Bus` 应显示 `Queue / Sync / Deliver` 三段式链路，承接中心创作链路和右侧检查控制台。
- 该结构必须是只读状态，不改变撤销、工具切换、时间轴空态 CTA 和指标展示行为。
- 第七轮样式独立放入新的最终 CSS layer，避免污染时间轴工具按钮和空态 CTA。

## 第八轮补充

第七轮后顶栏、中心、右侧和时间轴都有明确总线语义，但左侧命令轨道的 AI 导演入口仍只有 `Core` 徽标，缺少入口分发链路。第八轮补充要求：

- 左侧 AI 导演入口应暴露 `command-rail-flow` 语义，表达它是从需求输入到角色/镜头构建的命令入口。
- `Command Rail` 应显示 `Brief / Cast / Build` 三段式链路，承接顶栏 `Prompt / Shots` 和中心导演画布。
- 该结构必须是只读状态，不改变素材库、AI 导演、演员库和动捕实验室切换行为。
- 第八轮样式独立放入新的最终 CSS layer，避免污染已有命令轨道密度与第三轮 `Core` 徽标。

## 第九轮补充

第八轮后剪辑首屏主链路已较完整，但音频大师模式仍是独立空态舞台，只通过 `Input / Rhythm / Delivery` 卡片隐含流程，缺少和 Nebula Flow 一致的只读总线语义。第九轮补充要求：

- 音频大师舞台应暴露 `audio-bus` 语义，表达它是旁白、节奏与交付响度的母带总线。
- `Audio Bus` 应显示 `Input / Rhythm / Delivery` 三段式链路，承接时间轴和导出前交付检查。
- 该结构必须是只读状态，不改变“导入音频素材”按钮行为和既有状态塔、三列 lane。
- 第九轮样式独立放入新的最终 CSS layer，避免污染已有音频大师卡片密度和 Docker UI smoke 几何约束。

## 第十轮补充

第九轮后剪辑与音频大师链路已经接入总线，但实验室的监控子页面仍只是 `lab-watch-stage-shell` 包住监控面板，缺少从观测到修复再到发布的运维语义。第十轮补充要求：

- 实验室监控壳层应暴露 `watch-bus` 语义，表达它是系统运行态观测与修复的控制台入口。
- `Watch Bus` 应显示 `Observe / Repair / Release` 三段式链路，承接实验室治理、系统监控和最终交付。
- 该结构必须是只读状态，不改变 TelemetryDashboard 内容、实验室切换或监控面板交互。
- 第十轮样式独立放入新的最终 CSS layer，避免污染实验室长流程页面和 Docker UI smoke 几何约束。

## 第十一轮补充

第十轮后实验室监控子页面已具备运行态总线，但实验室默认比对舞台仍直接进入阶段导航和工具栏，缺少与 `Watch Bus` 对称的实验编排入口语义。第十一轮补充要求：

- 实验室默认舞台应暴露 `experiment-bus` 语义，表达它是模型比对、策略治理、创意闭环和协作治理的实验编排总线。
- `Experiment Bus` 应显示 `Compare / Govern / Ship` 三段式链路，承接视频实验室从比对到治理再到交付的主路径。
- 该结构必须是只读状态，不改变实验室阶段切换、工具栏按钮、通道接入弹窗或各子面板交互。
- 第十一轮样式独立放入新的最终 CSS layer，避免污染 `ComparisonLab.css` 的长流程布局和 Docker UI smoke 几何约束。
